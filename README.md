# Bank Transaction Clustering & Classification

A reproducible machine learning study of bank transaction segmentation using K-Means and PCA, followed by Decision Tree and Random Forest classifiers that reproduce the resulting cluster labels.

## Scope

The project explores transaction patterns rather than predicting verified fraud. `Target` is a **pseudo-label generated by K-Means**, not a ground-truth fraud label. The current representation uses LabelEncoder for categorical features, so distances between location codes are artificial and strongly influence the clusters.

## Run locally

Use Python 3.11. On Windows, from the repository root:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe scripts/run_notebooks.py
.\.venv\Scripts\python.exe scripts/validate_results.py
```

On macOS or Linux, create the environment with `python3.11 -m venv .venv` and use `.venv/bin/python` for the remaining commands. `requirements.lock.txt` records the versions used for the saved results; `requirements.txt` contains the direct dependency constraints. The tested environment uses scikit-learn 1.7.0 and Yellowbrick 1.5 on CPU.

Alternatively, select the project environment in Jupyter or VS Code, then run `01_clustering.ipynb` followed by `02_classification.ipynb`. The notebooks locate the repository from either its root or the notebooks directory. Data loading uses the included local CSV and does not require network access.

## Workflow

1. Explore numeric correlations, distributions, categories, identifiers, and timestamps.
2. Remove missing values and duplicate rows; exclude identifiers, IP addresses, and dates from model features.
3. Encode categories, remove numeric outliers using sequential IQR filtering, standardize numeric features, and create an age quantile feature.
4. Compare elbow distortion and silhouette scores, fit K-Means, and visualize the result with PCA. Fit a second K-Means model on the two PCA components.
5. Profile each cluster and restore original numeric units and category labels for interpretation.
6. Use an 80/20 stratified train-test split for Decision Tree and Random Forest classification. Tune Decision Tree using 5-fold CV on training data only.

Models are serialized with joblib using the `.joblib` extension. They are fitted estimators for these processed feature schemas, not complete deployment pipelines for raw transactions. Only load joblib artifacts you trust.

## Results

The input contains **2,537 rows and 16 columns**. Cleaning leaves **1,945 rows and 10 features**, plus `Target` in each exported CSV.

- Selected K: **2**, with cluster sizes **980** and **965**.
- Silhouette score: **0.572160**.
- Distortion elbow: K=4; K=2 is selected because it gives the highest silhouette among K=2..9. The notebook explains this tradeoff.
- Classifier split: **1,556 training rows** and **389 test rows**.

## Interpretation and limitations

Cluster 0 spans the encoded location range Albuquerque–Louisville; cluster 1 spans Memphis–Washington. Differences in average transaction amount and balance are relatively small. Every location in the cleaned data belongs to only one cluster, making the pseudo-labels easy for the classifiers to reproduce.

Preprocessing, categorical vocabulary, and clustering use the full dataset before the classifier split. Test scores therefore describe agreement with an existing partition, rather than independent end-to-end generalization to unseen raw transactions. IQR filtering also removes all login-attempt values above 1, which can discard observations relevant to anomaly analysis. These choices limit the interpretation of the results.

A stronger segmentation study could compare one-hot encoded categories, assess stability across resampling, and evaluate preprocessing and clustering within a separate training cohort. Fraud detection would additionally require verified outcome labels.
